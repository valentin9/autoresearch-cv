# Task Scope

## Description

Train a model to detect and classify the font family used in a text region of an image.
Given an input image containing rendered text, the model should identify which font family
(by name) was used to render that text.

The input is a cropped image patch containing text rendered in a single font.
The model outputs a font class label corresponding to the font family name.

**Scope**: font family only (not weight/style — Regular vs Bold vs Italic are the same class).
This is the right level for the production use case: image→HTML conversion where the goal
is to replicate text with the correct `font-family` in CSS.

Classes: one class per font family. The exact class list is defined in the metadata below.
All classes are Latin-script web fonts (Google Fonts + common system fonts) — the target
deployment is web/UI screenshot analysis for HTML replication.

**Research goal**: Find a novel approach that achieves strong font classification with limited
training data. Sample efficiency is a core research objective — the approach should not rely
on scale to succeed, and demonstrating good performance at 2k samples/class is part of what
makes it novel.

Known challenges:
- Fine-grained visual similarity between fonts (e.g. many sans-serifs look nearly identical)
- Variation in font size, color, background, and rendering quality
- Some fonts differ only subtly (e.g. Inter vs DM Sans vs Manrope)

This task is well-suited for synthetic data: render text strings using known fonts onto
varied backgrounds, then label by font name. See `tools/` for synthetic generation utilities.

Key properties of the dataset (generated by `tools/font_generator.py`):
- **Greyscale** (BW) images — color is irrelevant for glyph shape and only adds noise
- **Multi-line paragraphs** — 2–4 lines, ~12 chars/line wrap → ≥50 chars total per image
- **Tight letterbox crop** — text block fills ~55% of the 224×224 image; aspect ratio preserved (≤20% distortion)
- **Font size**: 36–72px rendered on a large canvas then letterboxed
- **Fonts**: Arial/Georgia/Times New Roman/Verdana from exact system paths; all others from Google Fonts via GitHub
- **Scale**: 2000 train / 400 val per class, 74 classes = 148k train / 29.6k val total

## Dataset Generation Notes (for reference / future tasks)

See `tools/font_generator.py` for the full implementation. Key decisions:

1. **Font sources**:
   - Arial, Georgia, Times New Roman, Verdana: exact system paths (see `SYSTEM_FONT_EXACT` dict)
   - All others: GitHub raw URLs from `google/fonts` repo (see `FONT_DIRECT_URLS` dict)

2. **Rendering**:
   - Multi-line paragraph, ≥50 chars, ~12 chars/line wrap
   - Greyscale (R=G=B), no colour jitter
   - Font size 36–72px, letterbox resize to 224×224
   - Light blur + noise augmentation (10% chance each)

3. **What NOT to do** (learned the hard way):
   - Don't use fuzzy system font search — it picks up wrong fonts (SFGeorgian, Roboto Mono)
   - Don't resize with squish — always letterbox
   - Don't truncate text below ~15 chars — use word wrap instead
   - Don't render single-line text at large font on a wide canvas — produces 9:1 crops

Target: 2000+ train / 400+ val per class, balanced.
